Analysis Result

The idle timer in SessionProvider is not reset by background refresh calls. When the refresh request and the timer expiry overlap, the client discards the new token and the next request is rejected with 401.

Root Cause

Race condition between the refresh-token response handler and the idle-timeout reset in the auth context.

Debug Checklist

Completed by Minh Tran · 05 Aug, 11:40

Solution Description

Refresh the access token before the idle timer expires and keep the session alive while the tab stays active. The refresh handler now resets the timer inside the same transaction.

Bug Description

From QA report

Actual Result

After about 12 minutes of continuous use the app returns to the sign-in screen and unsaved form data is lost.

Expected Result

The session stays alive while the user is active and the access token refreshes silently in the background.

Steps To Reproduce

  1. Sign in on staging with a standard account.
  2. Open the Orders list and keep scrolling and filtering.
  3. Wait until the 12th minute without reloading the page.
  4. Trigger any request, for example open an order detail.
